# INC-003 — Exchange Online: Incoming Emails Automatically Marked as Read

## Ticket Information

| Field | Details |
|---|---|
| Ticket ID | INC-003 |
| Category | Microsoft 365 / Exchange Online |
| Priority | P3 — Low |
| Affected User | Rachel Brooks |
| Sender | John Smith |
| Environment | Hybrid Active Directory / Microsoft Entra ID / Exchange Online |
| License | Microsoft 365 Business Basic |
| Status | Resolved |

## Incident Description

Rachel Brooks reported that emails from her coworker John Smith were appearing as already read in Outlook, despite her not opening them.

The messages were successfully delivered to her Inbox, but their read status was being changed automatically.

### Reported Symptoms

- Emails from John Smith arrived successfully.
- Messages appeared as read immediately upon arrival.
- The issue was reproducible with multiple test emails.
- No delivery failures or bounce-back messages were observed.
- Other Outlook functionality appeared normal.

## Environment

- On-premises Active Directory domain: `aden.local`
- Hybrid identity synchronization with Microsoft Entra ID
- Exchange Online mailboxes provisioned through Microsoft 365 Business Basic
- PowerShell 7 with the ExchangeOnlineManagement module

Test mailboxes:

- `jsmith@adensvaygmail.onmicrosoft.com`
- `rbrooks@adensvaygmail.onmicrosoft.com`

## Troubleshooting Process

### 1. Confirmed Mail Delivery

Sent an email from John Smith to Rachel Brooks through Outlook on the web.

**Result:** The email arrived successfully but was already marked as read.

### 2. Reproduced the Problem

Sent a second test email without manually opening or selecting it in Rachel's mailbox.

**Result:** The second message also appeared as read.

This established that the issue was reproducible.

### 3. Inspected Exchange Admin Center

Reviewed the relevant mailboxes through the Exchange Admin Center.

No obvious configuration problem was identified through the available GUI settings.

### 4. Inspected Inbox Rules with PowerShell

Connected to Exchange Online and ran:

```powershell
Get-InboxRule -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" |
    Format-List Name,Enabled,Description
```

**Output:**

```text
Name        : LAB-INC003-20cc7615
Enabled     : True
Description : If the message:
                the message was received from 'John Smith'
              Take the following actions:
                mark the message as Read
```

This revealed an enabled server-side inbox rule targeting messages from John Smith.

## Root Cause

An Exchange Online inbox rule was configured to automatically mark incoming messages from John Smith as read.

Because the rule executed during mailbox processing, the affected messages appeared as read before Rachel manually opened them.

This was a mailbox configuration issue rather than a mail transport failure.

## Remediation

Disabled the offending inbox rule:

```powershell
Disable-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" `
    -Identity "LAB-INC003-20cc7615"
```

Disabling the rule was preferable to immediately deleting it because the change was reversible.

## Verification

- Confirmed that the rule was disabled.
- Sent a fresh test email from John Smith to Rachel Brooks.
- Confirmed that the automatic read-status behavior no longer occurred.
- Verified that incoming mail continued to arrive normally.

**Resolution:** Successful.

# PowerShell Command Reference

## 1. Install Exchange Online PowerShell

```powershell
Install-Module ExchangeOnlineManagement -Scope CurrentUser
```

If prompted to trust PSGallery, review the repository information and approve the installation.

Import the module:

```powershell
Import-Module ExchangeOnlineManagement
```

## 2. Connect to Exchange Online

```powershell
Connect-ExchangeOnline -UserPrincipalName entraadmin@adensvaygmail.onmicrosoft.com
```

Requires appropriate Exchange administrative permissions.

## 3. List Exchange Online Mailboxes

```powershell
Get-EXOMailbox -ResultSize Unlimited |
    Select-Object DisplayName,PrimarySmtpAddress,RecipientTypeDetails |
    Format-Table -AutoSize
```

Useful for identifying provisioned mailboxes and verifying SMTP addresses.

## 4. View All Standard Inbox Rules for a User

```powershell
Get-InboxRule -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" |
    Format-List Name,Enabled,Description
```

Displays rule names, enabled states, and readable descriptions.

## 5. Inspect Detailed Rule Properties

```powershell
Get-InboxRule -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" |
    Format-List Name,Enabled,Priority,From,MarkAsRead,MoveToFolder,DeleteMessage,StopProcessingRules
```

Useful properties:

| Property | Purpose |
|---|---|
| Enabled | Indicates whether the rule is active |
| Priority | Rule processing order |
| From | Sender-based conditions |
| MarkAsRead | Marks matching messages as read |
| MoveToFolder | Moves messages into another folder |
| DeleteMessage | Deletes matching messages |
| StopProcessingRules | Prevents later rules from processing matching messages |

## 6. Include Hidden Inbox Rules

```powershell
Get-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" `
    -IncludeHidden |
    Format-Table Name,Enabled,Priority -AutoSize
```

Hidden rules are not automatically suspicious. Investigate their purpose before changing them.

## 7. Disable an Inbox Rule

```powershell
Disable-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" `
    -Identity "LAB-INC003-20cc7615"
```

Preferred when a reversible remediation is appropriate.

## 8. Re-enable an Inbox Rule

```powershell
Enable-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" `
    -Identity "LAB-INC003-20cc7615"
```

Useful for controlled rollback when authorized.

## 9. Remove an Inbox Rule

```powershell
Remove-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" `
    -Identity "LAB-INC003-20cc7615" `
    -Confirm:$false
```

Only remove rules after confirming they are unnecessary and documenting the change.

## 10. Verify Rule Status After Remediation

```powershell
Get-InboxRule `
    -Mailbox "rbrooks@adensvaygmail.onmicrosoft.com" |
    Format-List Name,Enabled,Description
```

The affected rule should show `Enabled : False` if it was disabled.

## 11. Disconnect from Exchange Online

```powershell
Disconnect-ExchangeOnline -Confirm:$false
```

Closes the administrative PowerShell session.

## Lessons Learned

1. Successful email delivery does not guarantee expected mailbox behavior.
2. Exchange Online inbox rules can automatically modify message properties.
3. The Exchange Admin Center does not expose every mailbox configuration through its GUI.
4. PowerShell provides a direct way to inspect and remediate server-side inbox rules.
5. Reproducing symptoms before making changes helps distinguish consistent problems from isolated behavior.
6. Disabling a problematic rule is often safer than deleting it immediately.
7. Always perform a fresh functional test after remediation.

## Other Potential Causes of Automatically Read Messages

Not every auto-read incident is caused by an inbox rule. Other possibilities include:

- Outlook reading-pane settings
- Another active Outlook session
- Mobile email clients
- Shared mailbox access
- Third-party mailbox integrations
- Automation interacting with Microsoft Graph or Exchange
