
# INC-001 — Active Directory Account Expiration

**Date:** October 8, 2026  
**Severity:** P3 — Standard Priority  
**Environment:** Windows Server 2022, Active Directory Domain Services  
**Affected User:** John Smith (`jsmith`)  
**Workstation:** `COMP01`  
**Status:** Resolved

## Incident Summary

A Sales employee reported being unable to sign into their Windows workstation despite successfully accessing it the previous day.

The employee encountered the following Windows authentication error:

> Your account has expired. Please see your system administrator.

The objective was to identify the cause of the authentication failure, verify that restoring access was authorized, implement the minimum necessary correction, and confirm successful sign-in.

## Environment

- Active Directory domain: `aden.local`
- Domain controller: Windows Server 2022
- Client: Windows 11 (`COMP01`)
- Identity: On-premises AD account synchronized with Microsoft Entra ID
- Management tools: ADUC, Windows PowerShell, Active Directory module

## Investigation

### 1. Gathered user information

Requested the exact Windows error message, affected workstation, and employee identifier.

The employee confirmed the error occurred at the Windows sign-in screen on `COMP01`.

### 2. Reviewed Active Directory account state

Used PowerShell to establish the initial account baseline:

```powershell
Get-ADUser jsmith -Properties `
    LockedOut,PasswordExpired,LastLogonDate,LogonWorkstations |
    Format-List Name,Enabled,LockedOut,PasswordExpired,`
    LastLogonDate,LogonWorkstations
```

Initial observations:

- Account enabled: True
- Account locked: False
- Password expired: False
- Authorized workstation: COMP01

These findings helped distinguish an account-expiration problem from a lockout or expired-password problem.

### 3. Identified the root cause

Investigated the account expiration configuration in Active Directory Users and Computers.

The account expiration date was October 6, 2026, two days before the incident.

This prevented the employee from authenticating even though the account remained enabled.

## Authorization and Risk Assessment

Before modifying the account, escalated the employment-status question to HR.

HR confirmed that the employee had transitioned from temporary contractor to permanent full-time employment and authorized removing the account expiration restriction.

This step was necessary because expired accounts may represent legitimate access revocation.

**Key principle:** Technical permissions to modify an account do not automatically establish authorization to restore access.

## Remediation

Opened the affected user in Active Directory Users and Computers:

1. Located the `jsmith` account.
2. Opened **Properties → Account**.
3. Changed **Account expires** to **Never**.
4. Applied the account configuration.

No password resets, group membership changes, or unrelated account modifications were required.

Equivalent PowerShell remediation:

```powershell
Clear-ADAccountExpiration -Identity "jsmith"
```

The PowerShell command is included as an alternative method, not as a command executed during this incident.

## Verification

The employee was asked to attempt Windows sign-in again.

The employee confirmed:

- Successful authentication to COMP01
- Access to the Windows desktop
- Access to required files

For additional administrative verification, the following read-only command can be used:

```powershell
Get-ADUser jsmith -Properties AccountExpirationDate |
    Select-Object Name,Enabled,AccountExpirationDate
```

Expected result: `AccountExpirationDate` is empty.

## Root Cause

An outdated account expiration date remained configured after the employee transitioned from contractor to permanent employee.

The identity lifecycle process had not updated the account's expiration configuration.

## Resolution

Removed the obsolete account expiration restriction following HR authorization.

User confirmed successful workstation access.

**Final status:** Resolved.

## Lessons Learned

1. An enabled account can still be prevented from authenticating due to account expiration.
2. Account expiration and password expiration are separate Active Directory properties.
3. Account recovery must include employment and authorization verification.
4. The least disruptive correction is preferable to unnecessary password resets or account recreation.
5. Employee lifecycle changes should trigger corresponding identity updates.

## Preventive Recommendation

Implement an HR-to-IT account lifecycle checklist for contractor-to-employee conversions, including account expiration, group memberships, licensing, and access review.
