
# INC-035 — Network Connectivity Failure (Missing Default Gateway / Default Route)

**Date:** October 26, 2026  
**Priority:** P3 — Medium  
**Category:** Network Troubleshooting / IPv4 Routing  
**Environment:** Windows 11, VMware Workstation  
**Affected Device:** Standalone Windows 11 test VM (referred to as COMP03; OS hostname reported COMP02)  
**Network Interface:** Ethernet0  
**Status:** Resolved

---

## 1. Incident Summary

A simulated Operations Department employee reported that their workstation appeared connected to the network but could not access the internet.

### User Report

> "Hi IT, my computer says it's connected to the network, but I can't access the internet. I've tried multiple websites and restarted Chrome. My coworkers don't seem to have the same problem. Could you take a look?"

### Symptoms

- Workstation could not access external websites.
- External IPv4 connectivity failed.
- DNS resolution was successful.
- DHCP was enabled.
- Workstation had a valid private IPv4 address.
- No default gateway appeared in the workstation's IP configuration.

### Root Cause

The workstation's IPv4 default route (`0.0.0.0/0`) was missing.

Without a default route, Windows had no route for forwarding traffic to external IPv4 destinations that did not match a more specific route.

The workstation could still communicate with devices on its local subnet, including its DNS resolver.

### Resolution

Renewed the workstation's DHCP lease using:

```powershell
ipconfig /renew
```

The DHCP renewal restored the default gateway configuration.

The workstation subsequently regained internet access.

## 6. Root Cause Analysis

### What Is a Default Gateway?

A default gateway is a router used by a workstation to forward traffic to destinations outside its directly connected network.

In this environment:

```text
Workstation IP: 192.168.254.78
Subnet Mask:    255.255.255.0
Local Subnet:   192.168.254.0/24
Gateway:        192.168.254.254
```

The workstation can communicate directly with devices on `192.168.254.0/24`.

For destinations outside that subnet, it needs an appropriate route.

### What Is a Default Route?

The IPv4 default route is represented as:

```text
0.0.0.0/0
```

This route matches any IPv4 destination but is used only when no more specific matching route takes precedence.

A functioning default route for this workstation would resemble:

```text
Destination: 0.0.0.0/0
Next Hop:    192.168.254.254
Interface:   Ethernet0
```

### Expected Traffic Flow

```text
Windows Workstation
192.168.254.78
       |
       | Destination: 8.8.8.8
       v
Default Route: 0.0.0.0/0
       |
       v
Default Gateway
192.168.254.254
       |
       v
External Network / Internet
```

### Actual Traffic Flow

The default route was removed.

```text
Windows Workstation
192.168.254.78
       |
       | Destination: 8.8.8.8
       v
No matching route to external destination
       |
       X
Traffic cannot be forwarded
```

### Why DNS Still Worked

The configured DNS server was `192.168.254.254`, which belonged to the same local subnet as the workstation.

Windows could communicate directly with that address using its connected subnet route.

Therefore:

- `nslookup google.com` succeeded.
- `ping 8.8.8.8` failed.
- External websites were inaccessible.

**Root Cause:** Missing IPv4 default route on Ethernet0.

## 7. Remediation

### Step 1 — Renew DHCP Configuration

Command executed:

```powershell
ipconfig /renew
```

Output:

```text
Windows IP Configuration

Ethernet adapter Ethernet0:

   Connection-specific DNS Suffix  . : home
   Link-local IPv6 Address. . . . . : fe80::b08e:bd3:2ae2:d2bc%4
   IPv4 Address. . . . . . . . . . . : 192.168.254.78
   Subnet Mask . . . . . . . . . . . : 255.255.255.0
   Default Gateway . . . . . . . . . : 192.168.254.254
```

### Analysis

The DHCP renewal restored the workstation's default gateway configuration.

The workstation retained its existing IPv4 address:

```text
192.168.254.78
```

The default gateway was restored to:

```text
192.168.254.254
```

Because DHCP was already enabled and the DHCP server was functioning, renewing the lease was sufficient to restore the missing gateway.

### Why DHCP Renewal Worked

A DHCP server can provide several network configuration parameters, including:

- IPv4 address
- Subnet mask
- Default gateway
- DNS servers
- Lease duration

When the workstation renewed its DHCP lease, Windows reapplied the gateway configuration provided by DHCP.

This restored the default route needed for external IPv4 connectivity.

## 8. Alternative Remediation — Manual Default Route

A default route can also be created manually using PowerShell.

**Reference command (recommended during troubleshooting; execution not confirmed in the captured session):**

```powershell
New-NetRoute `
    -InterfaceAlias "Ethernet0" `
    -DestinationPrefix "0.0.0.0/0" `
    -NextHop "192.168.254.254" `
    -RouteMetric 10
```

### Command Explanation

| Parameter | Purpose |
|---|---|
| `New-NetRoute` | Creates a new routing table entry |
| `-InterfaceAlias "Ethernet0"` | Selects the network interface |
| `-DestinationPrefix "0.0.0.0/0"` | Specifies the IPv4 default route |
| `-NextHop "192.168.254.254"` | Specifies the gateway/router |
| `-RouteMetric 10` | Assigns a route preference metric |

### Important Consideration

For a DHCP-managed workstation, DHCP renewal is generally preferable to maintaining an unnecessary manually configured default route.

A manual route may be appropriate in certain static addressing or advanced routing scenarios.

Before adding or removing routes, inspect the existing routing table to avoid creating duplicate or conflicting entries.

## 12. Lessons Learned

### Technical Lessons

1. A valid IPv4 address does not guarantee internet connectivity.
2. A workstation needs an appropriate route to reach destinations outside its local subnet.
3. The default route `0.0.0.0/0` identifies where traffic should go when no more specific route matches.
4. The default gateway is the router used as the next hop for the default route.
5. DNS resolution can work without a default gateway when the DNS server is reachable on the local subnet.
6. DHCP can provide gateway information in addition to IP addressing and DNS settings.
7. Renewing a DHCP lease can restore missing gateway configuration.
8. Routing tables should be inspected before manually adding or removing routes.

### Troubleshooting Lessons

- Start by verifying the reported symptom.
- Test external IP connectivity independently of DNS.
- Inspect the assigned IP address, subnet mask, and default gateway.
- Determine whether the problem affects local communication or external routing.
- Prefer the smallest effective remediation.
- Verify application functionality after restoring network configuration.

### PowerShell Development

Retrieves routing table entries.


Creates routing table entries.

Retrieves interface configuration, including IPv4 addresses and gateway information.

The most important concept is understanding the relationship between the destination prefix, next hop, and network interface.
