
# INC-019 — SharePoint Online Document Permission Restoration

**Category:** Microsoft 365 / SharePoint Online  
**Environment:** Hybrid AD / Microsoft Entra ID / Microsoft 365  
**Priority:** P3 — Standard User Access Request  
**Affected User:** Rachel Brooks (HR Coordinator)  
**Document Owner:** John Smith  
**SharePoint Site:** `testing`  
**Administrative Account:** `entraadmin@adensvaygmail.onmicrosoft.com`  
**Exercise Type:** Guided administration and permission troubleshooting  
**Status:** Permission restoration verified in SharePoint; user-side edit test and admin access cleanup pending confirmation

---

## 1. Incident Summary

Rachel Brooks reported that she could open a SharePoint document shared by John Smith but could no longer edit its contents.

The exercise involved reproducing a View-only permission state, obtaining authorized administrative access to the SharePoint site, and restoring Rachel's direct Edit permission.

A secondary administrative challenge was encountered: the tenant administrator account did not initially have direct access to the SharePoint site's content.

## 2. Environment and Initial State

- SharePoint Online test site: `testing`
- Document owned or originally shared by John Smith
- Rachel Brooks previously had working Edit access
- Rachel's access was deliberately changed to View-only to reproduce the incident
- Administrator account: `entraadmin@adensvaygmail.onmicrosoft.com`
- Microsoft 365 sign-in sessions for John Smith and the administrator required separation during testing

**Known-good baseline:** Rachel could open and edit the document before fault staging.

**Reproduced issue:** Rachel's access was reduced to View-only.

## 3. Administrative Investigation

The administrator attempted to access the SharePoint site and manage document permissions but encountered access limitations.

This highlighted the distinction between:

- **Tenant-level administrative roles:** SharePoint Administrator or Global Administrator
- **Site collection administrator:** Full administrative control over a specific SharePoint site collection
- **Document-level permissions:** Direct or inherited View/Edit permissions granted to users

A tenant administrator does not automatically receive routine content access to every SharePoint site. Appropriate tenant-level authority can be used to assign site collection administrators when authorized.

### Administrative Access Procedure

Using the SharePoint admin center:

1. Signed in using the `entraadmin` account.
2. Opened **Sites → Active sites**.
3. Located and selected the SharePoint site named `testing`.
4. Opened the site's administrator management interface.
5. Added `entraadmin` as a **site administrator**.
6. Confirmed the SharePoint admin center displayed:

   `entraadmin was added as a site admin`

**Result:** The administrator account obtained site-level administrative access to the `testing` SharePoint site.

**Security note:** This was a temporary administrative elevation for an authorized lab exercise. In production, elevated access should follow organizational approval, least-privilege, and audit procedures.

## 4. Resolution

After obtaining site administrator access:

1. Opened the SharePoint test site using the administrator account.
2. Navigated to the affected document.
3. Opened **Manage access**.
4. Located Rachel Brooks under the document's direct access permissions.
5. Restored Rachel's permission to **Can edit**.
6. Reviewed the access summary to confirm the new permission.

The SharePoint interface displayed:

```text
Rachel Brooks can edit

Ways this person has access:
Direct Access: can edit
```

**Result:** SharePoint confirmed that Rachel's direct permission was restored to Edit.

No tenant-wide sharing policies, default site permissions, or other users' permissions were intentionally changed.

The permission change is verified at the SharePoint administration level. End-user functional verification remains a recommended final step.

## 6. Cleanup and Security

After confirming Rachel can edit and save the document:

1. Return to **SharePoint admin center → Active sites → testing**.
2. Open **Site admins**.
3. Remove `entraadmin` from the site's administrators if elevated access is no longer required.
4. Confirm that the original authorized site administrators remain assigned.
5. Verify Rachel retains the intended document permissions.

Do not remove the tenant-level SharePoint Administrator or Global Administrator role as part of this cleanup; the temporary elevation in this exercise was **site-level**.

## 7. Root Cause

**Lab-induced permission change:** Rachel's document permission was deliberately reduced from Edit to View.

The administrative access obstacle was separate: the administrator needed site collection administrator access to manage permissions on the selected SharePoint site.

This was not an authentication outage, licensing failure, or SharePoint service incident.

## 8. Key Takeaways

- Tenant-level administrative authority and SharePoint content access are separate permission layers.
- A SharePoint Administrator can assign site administrators to support authorized site-level administration.
- Site collection administrators have broad access to content and permissions within their site collection.
- Direct document permissions can differ from inherited permissions granted through sites, libraries, or groups.
- Permission changes should be narrowly scoped to the affected user and resource.
- Temporary elevated access should be removed after resolution.
- Administrative confirmation and end-user functional testing are distinct verification steps.
