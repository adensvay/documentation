## 1. Incident Summary

### User Report

John Smith, a Sales employee, reported that ChatGPT was missing from his Windows 11 workstation despite being a required application for his department.

Other Sales employees reportedly had access to the application.

### Expected Behavior

ChatGPT should automatically install through Microsoft Intune when the user is included in the targeted security group and the device meets deployment requirements.

### Actual Behavior

ChatGPT was not installed on COMP01.

Intune initially reported `Not applicable`, later changing to:

`Failed — Unknown (0x00000000)`

## 3. Investigation

### Phase 1 — Security Group Membership

**Finding:** John Smith was missing from the `SG-Sales` security group.

Since ChatGPT was assigned as a required application to this group, the missing membership was a potential cause of the deployment issue.

**Actions:**

1. Inspected security group membership in Entra ID.
2. Obtained simulated HR authorization to restore Sales access.
3. Restored `jsmith` to `SG-Sales`.
4. Initiated an Intune device synchronization.

**Result:** Group membership corrected. ChatGPT installation remained unverified.

### Phase 2 — Device Registration

On COMP01, executed:

```powershell
dsregcmd /status
```

Device state:

```text
AzureAdJoined : YES
DomainJoined  : YES
DomainName    : ADEN
Device Name   : comp01.aden.local
```

Also verified the device's management connection under:

`Settings > Accounts > Access work or school`

**Result:** Hybrid Entra join and an MDM management connection were present.

### Phase 3 — Cloud Authentication Failure

Inspected the SSO State section of `dsregcmd /status`.

Initial findings:

```text
AzureAdPrt : NO
User Identity : jsmith@aden.local
HTTP Status : 400
Server Error : invalid_request
AADSTS90002 : Tenant 'aden.local' not found
```

**Diagnosis:**

The on-premises UPN used the internal `aden.local` suffix, while John's synchronized Entra identity used the tenant's `onmicrosoft.com` suffix.

This caused tenant discovery to fail during the Entra PRT authentication attempt.

Windows domain authentication succeeded, but cloud SSO authentication failed.

### Phase 4 — UPN Remediation

On the domain controller:

```powershell
Get-ADUser jsmith -Properties UserPrincipalName |
    Select-Object Name,SamAccountName,UserPrincipalName
```

Original UPN:

```text
jsmith@aden.local
```

Changed the UPN in Active Directory Users and Computers to:

```text
jsmith@adensvaygmail.onmicrosoft.com
```

Verified the updated attribute.

Triggered Entra Connect synchronization:

```powershell
Import-Module ADSync

Start-ADSyncSyncCycle -PolicyType Delta
```

Output:

```text
Result
------
Success
```

Restarted COMP01 and signed back in as `ADEN\jsmith`.

Verified the Windows session identity:

```powershell
whoami /upn
```

Result:

```text
jsmith@adensvaygmail.onmicrosoft.com
```

Rechecked:

```powershell
dsregcmd /status
```

Updated result:

```text
AzureAdPrt : YES
```

**Result:** The user's cloud SSO issue was resolved.

### Phase 5 — Intune Deployment Monitoring

Performed a manual Intune synchronization.

Navigated to:

`Intune > Apps > Windows > ChatGPT > Device install status`

Initial result:

```text
Status: Not applicable
```

After reporting updated:

```text
Device: COMP01
User: jsmith@adensvaygmail.onmicrosoft.com
Status: Failed
Error: Unknown (0x00000000)
```

Intune showed:

- Application assigned to SG-Sales.
- Device successfully checking in.
- Application installation failure.
- No actionable error description.

**Result:** Application deployment failure confirmed.

### Phase 6 — Local Application Verification

On COMP01, under John's Windows session:

```powershell
Get-AppxPackage |
    Where-Object {
        $_.Name -match "ChatGPT|OpenAI|Zoom|Teams"
    } |
    Select-Object Name,Version,Status
```

Observed:

| Application | Result |
|---|---|
| Microsoft Teams | Registered — OK |
| OneMeeting | Registered — OK |
| ChatGPT | Not detected |

Opened Microsoft Store and located the official ChatGPT application published by OpenAI.

The application displayed a **Get** button.

No manual installation was performed to avoid masking the managed deployment failure.

**Result:** ChatGPT was not installed for the affected user.

## 4. Root Cause Analysis

### Confirmed Issue #1 — Missing Security Group Membership

John was missing from the security group targeted by the required application assignment.

**Resolution:** Restored authorized SG-Sales membership.

### Confirmed Issue #2 — Hybrid Identity UPN Mismatch

The user's on-premises UPN was incompatible with Entra tenant discovery during PRT acquisition.

**Resolution:**

- Updated on-premises UPN.
- Triggered Entra Connect synchronization.
- Restarted the client.
- Verified `AzureAdPrt: YES`.

### Unresolved Issue #3 — Intune Application Deployment

ChatGPT continued to fail installation after group membership and cloud authentication were corrected.

Reported error:

```text
Failed — Unknown (0x00000000)
```

**Root cause: UNDETERMINED**

Potential areas for further investigation:

- Microsoft Store package applicability.
- Intune user-context installation requirements.
- App assignment and targeting evaluation.
- Windows AppX deployment events.
- Microsoft Store installation services.
- Intune device diagnostics.

These are hypotheses, not confirmed causes.

## 7. Technician Reflection

This incident began as a straightforward missing-application request but exposed multiple problems across the Microsoft identity and endpoint management stack.

The initial security group issue was resolved, but further investigation uncovered a genuine hybrid identity misconfiguration.

The most significant finding was the failed Entra PRT acquisition caused by the on-premises UPN mismatch.

Correcting the UPN restored cloud SSO, but did not resolve the Intune application deployment failure.

### Key Lessons

- Windows domain authentication and Entra cloud authentication are separate processes.
- Hybrid device registration does not guarantee successful user cloud SSO.
- Security group membership controls deployment targeting but does not guarantee installation.
- Successful Intune synchronization does not guarantee application deployment.
- Intune reporting may lag behind endpoint activity.
- Ambiguous installation errors require additional diagnostic evidence.
- An incident should not be marked resolved without verifying the original user-facing issue.
- Escalation and documentation are appropriate when the root cause cannot be identified within the troubleshooting timebox.
