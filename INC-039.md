
# INC-039 — Windows Print Spooler Service Failure

**Date:** October 27, 2026  
**Category:** Windows Desktop Support / Printer Troubleshooting  
**Priority:** P3 — Medium  
**Affected Host:** COMP02  
**Operating System:** Windows 11  
**Environment:** VMware Workstation  
**Status:** Resolved

---

## 1. Incident Summary

A simulated employee reported being unable to print documents from a Windows 11 workstation.

The printer had previously been installed and tested successfully using a physical network printer.

During investigation, Windows displayed an error indicating that the local Print Spooler service was not running.

PowerShell confirmed that the Print Spooler service was stopped and disabled.

The service startup configuration was restored to Automatic, the service was started, and a physical Windows test page was successfully printed from COMP02.

## 5. Fault Injection

The Print Spooler was deliberately stopped and disabled to simulate a Windows printing failure.

### Commands Executed

```powershell
Stop-Service -Name Spooler -Force
Set-Service -Name Spooler -StartupType Disabled
```

### Purpose

`Stop-Service` stops the running service.

`-Force` allows PowerShell to stop the service even when dependent services are involved.

`Set-Service` modifies the service's startup configuration.

Setting the startup type to Disabled prevents the service from being started normally.

### Verification Command

```powershell
Get-Service Spooler | Format-List Name, DisplayName, Status, StartType
```

### Output

```text
Name        : Spooler
DisplayName : Print Spooler
Status      : Stopped
StartType   : Disabled
```

### Result

The fault injection succeeded.

The Print Spooler was stopped and disabled.

## 7. Root Cause

The Windows Print Spooler service was configured as:

```text
Status: Stopped
StartupType: Disabled
```

The Print Spooler manages print jobs and interactions between Windows applications, printer queues, and installed printers.

When the service is stopped, Windows may be unable to process print jobs or manage printers normally.

Because the startup type was Disabled, the service could not start normally until its configuration was changed.

### Root Cause Classification

Windows service misconfiguration.

**Lab cause:** Deliberate fault injection.

---

## 8. Remediation

The remediation required two separate actions:

1. Restore the service startup type.
2. Start the service.

### Step 1 — Restore Automatic Startup

Command executed:

```powershell
Set-Service -Name Spooler -StartupType Automatic
```

### Intermediate Verification

Command executed:

```powershell
Get-Service Spooler | Format-List Name, DisplayName, Status, StartType
```

### Output

```text
Name        : Spooler
DisplayName : Print Spooler
Status      : Stopped
StartType   : Automatic
```

### Important Observation

Changing the startup type to Automatic did not immediately start the service.

The service remained stopped.

This demonstrated that startup configuration and service status are separate properties.

### Step 2 — Start the Service

Command executed:

```powershell
Start-Service -Name Spooler
```

### Step 3 — Verify Recovery

Command executed:

```powershell
Get-Service Spooler | Format-List Name, DisplayName, Status, StartType
```

### Output

```text
Name        : Spooler
DisplayName : Print Spooler
Status      : Running
StartType   : Automatic
```

### Result

The Print Spooler service was restored to its original configuration.

## 12. Printer Configuration Discovery

After restoring printing, inspected the installed printers.

### Command Executed

```powershell
Get-Printer | Format-Table Name, PortName, PrinterStatus -AutoSize
```

### Relevant Output

```text
Name                                      PortName
----                                      --------
NPI6B7C09 (HP Color LaserJet MFP M281cdw) WSD-ec789ad2-147b-43a1-8fbf-34493e3a2e9a
Microsoft Print to PDF                    PORTPROMPT:
```

Both printers reported `Normal` status.

### Printer Port Inspection

Command executed:

```powershell
Get-PrinterPort | Format-Table Name, PrinterHostAddress -AutoSize
```

The HP printer was associated with a WSD port.

No IPv4 address was displayed in the `PrinterHostAddress` field for that port.

### Finding

The printer was installed using a WSD port rather than a Standard TCP/IP port.

WSD allows Windows to discover and communicate with supported network printers.

A WSD port does not expose its destination through `PrinterHostAddress` in the same way as a Standard TCP/IP printer port.

This finding will inform the next printer troubleshooting exercise.

## 13. Lessons Learned

### Windows Printing Depends on the Print Spooler

A network printer can be powered on and reachable while printing remains unavailable because of a Windows-side service failure.

Printer troubleshooting should consider both the endpoint and the physical printer.

### Service Startup Type vs. Service Status

`StartType` controls how a service starts.

`Status` indicates whether the service is currently running.

These properties must be evaluated independently.

### Troubleshoot the Endpoint Before Reconfiguring the Printer

The physical printer was functioning normally.

The issue was caused by COMP02's local Print Spooler service.

Changing the printer's IP address, reinstalling drivers, or resetting the printer would not have addressed the identified root cause.

### Verify the User's Original Task

A service reporting `Running` is not sufficient evidence that printing works.

The successful physical test page provided end-to-end verification.

### Printer Ports Matter

Windows can install network printers through different port types, including WSD and Standard TCP/IP.

Understanding the configured port helps distinguish local print processing failures from network destination problems.
