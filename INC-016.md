
# INC-017 — Active Directory Account Expiration

**Category:** Identity & Access Management / Active Directory  
**Priority:** P3 — Normal  
**Environment:** Windows Server 2022, Active Directory, Windows 11  
**Affected User:** John Smith (`jsmith`)  
**Department:** Sales  
**Affected Workstation:** COMP01  
**Status:** Resolved in simulation — final technical verification pending

---

## 1. Incident Summary

A user reported being unable to sign in to their Windows 11 workstation.

The user received the following error:

> "Your account has expired. Please see your system administrator."

The objective was to investigate the authentication failure, determine whether the account expiration was intentional, obtain appropriate authorization, and restore access.

## 2. Environment

- **Domain:** `aden.local`
- **Domain Controller:** Windows Server 2022
- **Client:** Windows 11 (`COMP01`)
- **Affected Account:** `jsmith`
- **Administrative Tools:** Active Directory Users and Computers (ADUC), PowerShell

## 3. Initial Investigation

The technician contacted the user to gather additional information.

Requested information included:

- Exact Windows sign-in error
- Department
- Affected workstation
- Employee ID for account lookup

The user identified the affected device as `COMP01` and confirmed that Windows displayed an account expiration error.

### PowerShell — Initial Account Verification

On the domain controller, the following command was executed:

```powershell
Get-ADUser jsmith -Properties Enabled,LockedOut,AccountExpirationDate,LogonWorkstations |
    Select-Object Name,Enabled,LockedOut,AccountExpirationDate,LogonWorkstations
```

Initial output, before the fault injection:

```text
Name                  : John Smith
Enabled               : True
LockedOut             : False
AccountExpirationDate :
LogonWorkstations     : WIN-8QGPUAN7QO8,COMP01
```

This established that the account was initially enabled, unlocked, and had no expiration date.

The incident was then simulated by configuring an expired account date in Active Directory.

## 4. Root Cause Identification

The technician opened Active Directory Users and Computers:

1. Located the `jsmith` account.
2. Opened **Properties**.
3. Navigated to the **Account** tab.
4. Examined the **Account expires** setting.

The account expiration date was set to:

**October 13, 2026**

Because the account expiration date had passed, the user was unable to authenticate normally.

**Root cause:** Expired Active Directory user account.

## 5. Authorization and Escalation

Before modifying the account, the technician contacted Human Resources to verify whether the user was authorized to continue accessing company systems.

The simulated HR representative confirmed:

- John Smith remained an active employee.
- His previous temporary assignment had been extended.
- His approved assignment continued through December 31, 2026.
- IT was authorized to update the account expiration date.

This step was necessary because account expiration can reflect an intentional employment or access restriction.

**Security consideration:** Employee information alone is not sufficient identity verification. Production environments should follow established identity-verification and authorization procedures.

## 6. Resolution

Using Active Directory Users and Computers:

1. Opened the affected user's account properties.
2. Selected the **Account** tab.
3. Located the **Account expires** setting.
4. Changed the expiration date from October 13, 2026, to December 31, 2026.
5. Saved the updated account settings.

No password reset, group membership modification, or account recreation was required.

### PowerShell — Final Verification

The following command can be used to verify the updated AD account properties:

```powershell
Get-ADUser jsmith -Properties Enabled,AccountExpirationDate |
    Select-Object Name,Enabled,AccountExpirationDate
```

Expected result:

```text
Name       Enabled AccountExpirationDate
----       ------- ---------------------
John Smith True    12/31/2026 12:00:00 AM
```

**Verification note:** This is the expected result, not captured command output. The final PowerShell verification had not yet been supplied at the time of documentation.

## 7. User Validation

The technician requested that the user attempt another sign-in to `COMP01`.

The simulated user confirmed that sign-in was successful and that the Windows desktop was accessible.

This confirms the expected resolution within the ticket simulation.

A real interactive sign-in test on `COMP01` was not independently documented.

## 8. Evidence

Screenshots captured during the exercise:

1. **Before:** ADUC showing account expiration on October 13, 2026.
2. **After:** ADUC showing account expiration changed to December 31, 2026.

Screenshots demonstrate the configured values, but the updated setting should also be verified after saving.

## 9. Resolution Summary

The user's authentication issue was attributed to an expired Active Directory account.

The technician confirmed the account expiration, obtained simulated HR authorization, and updated the expiration date to match the approved assignment period.

The simulated user subsequently confirmed successful workstation access.

**Final status:** Resolved in the service desk simulation; saved AD setting and actual workstation authentication should be verified separately.

## 10. Key Takeaways

- Account expiration is distinct from account disablement and lockout.
- ADUC provides a graphical method for inspecting and modifying account expiration.
- `Get-ADUser` can be used to verify account status and expiration properties.
- Account expiration changes should require appropriate business authorization.
- Technicians should distinguish technical problems from intentional access restrictions.
- User confirmation and independent technical verification are both important.
- Administrative changes should be documented with their justification and verification results.
