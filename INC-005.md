# INC-005 — Intune Device Restriction No Longer Applying

## Environment

- Microsoft Intune
- Microsoft Entra ID
- Windows 11
- Microsoft Graph PowerShell
- Entra security groups
- Intune configuration profiles
- MDM-managed endpoint

### Relevant Objects

- User: John Smith
- UPN: `jsmith@adensvaygmail.onmicrosoft.com`
- Device: `COMP01`
- Entra Group: `SG-Sales`
- Intune Profile: `Device Restriction`
- Configuration Setting: `Gaming = Block`

---

## User Report

John Smith reported that a Windows restriction that normally applied to his managed workstation was no longer being enforced.

The device otherwise appeared to be functioning normally, and restarting the computer did not restore the restriction.

Ticket status:

`NEW → ACTIVE`

---

## Initial Investigation

The issue appeared to involve endpoint configuration rather than authentication.

John could:

- Sign into the device normally
- Use the computer normally
- Access company resources

The problem was limited to an expected Windows restriction no longer being enforced.

Because `COMP01` is managed through Intune, I began investigating the configuration policies and assignments affecting the user and device.

---

## Intune Configuration

An existing Intune configuration profile was identified:

`Device Restriction`

The profile contained the expected configuration:

`Control Panel and Settings → Gaming → Block`

The policy itself had not been deleted or incorrectly configured.

This shifted the investigation from:

> "Does the correct configuration exist?"

to:

> "Is the correct configuration being delivered to the intended users?"

---

## Investigation

I reviewed:

- The `SG-Sales` Entra security group
- Existing Intune configuration profiles
- Intune compliance policies
- The `Device Restriction` profile
- The profile's assignments

The `Device Restriction` configuration still existed with the expected setting.

However, the expected `SG-Sales` assignment was missing.

This broke the policy delivery path:

`Device Restriction`

↓

`SG-Sales`

↓

`John Smith`

↓

`COMP01`

Without the group assignment, the configuration profile still existed in Intune but was no longer targeted at the intended users.

---

## Root Cause

The `Device Restriction` Intune configuration profile had lost its assignment to the `SG-Sales` Entra security group.

The policy configuration itself remained intact.

This demonstrated an important distinction:

**Policy existence does not imply policy application.**

An Intune policy requires an appropriate assignment before its settings can be delivered to the intended users or devices.

---

## Resolution

Instead of creating a duplicate configuration profile, I restored the existing `Device Restriction` profile's assignment to:

`SG-Sales`

The resulting configuration was:

`Device Restriction → SG-Sales → Gaming: Block`

No excluded groups were configured.

The existing policy was reused rather than creating an unnecessary replacement.

Ticket status:

`ACTIVE → AWAITING CLIENT`

## Key Takeaways

### 1. Policy existence does not mean policy application

Finding the correct configuration profile in Intune does not prove that the policy is reaching the intended endpoint.

A useful troubleshooting chain is:

`Policy exists`

↓

`Settings are correct`

↓

`Assignment is correct`

↓

`User/device is in scope`

↓

`Device receives policy`

↓

`Setting applies`

A failure anywhere in this chain can prevent the intended configuration from reaching the endpoint.

### 2. Check assignments before recreating policies

My initial thought was to create a new policy because I could not find an active restriction affecting the user.

Before doing so, I inspected the existing profile more closely.

The configuration already existed; only its assignment was missing.

Creating another policy would have introduced unnecessary duplication and potentially created conflicting configurations.

### 3. Entra groups can provide Intune targeting

`SG-Sales` exists as an Entra security group.

Intune can use that group as an assignment target:

`Entra group → Intune configuration profile`

This does not make `SG-Sales` an "Intune group." Entra owns the identity/group object, while Intune consumes it for policy targeting.

### 4. Configuration and compliance are different

A configuration profile defines settings that should be applied to an endpoint.

A compliance policy evaluates whether a device satisfies organizational requirements.

Therefore, troubleshooting a missing Windows restriction should focus first on configuration profiles and their targeting rather than assuming that device compliance is the cause.

### 5. Restore known-good configuration

The existing policy was already correctly configured.

The appropriate remediation was therefore to restore its intended assignment rather than changing unrelated settings or creating a replacement policy.
