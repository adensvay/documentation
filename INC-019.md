## 1. Incident Summary

A user reported being unable to print documents from their Windows 11 workstation.

Initial investigation using PowerShell Remoting revealed that the Windows Print Spooler service was unreachable. Further inspection showed that the service was stopped and its startup type was disabled.

The service was reconfigured to start automatically and was started remotely. Windows subsequently recognized Microsoft Print to PDF as a healthy printer, and the previously encountered printer error no longer appeared.

## 3. Reported Symptoms

The user reported that printing was not working.

During troubleshooting, the Windows system print dialog displayed:

> Check your printer or select another printer. The printer you chose isn't available or isn't installed correctly.

The Windows printer settings interface remained accessible, but that alone did not confirm that the printing subsystem was functional.

### Initial Observations

- Windows printer settings could be opened.
- A PDF could be generated through an application workflow.
- Printing through the Windows system print dialog produced an error.
- No physical printer was required because Microsoft Print to PDF was available as a virtual printer.

**Important:** Exporting or saving a document as a PDF is not equivalent to submitting a job through the Windows printing subsystem.

## 4. Investigation

### Step 1 — Enumerate Installed Printers

From the domain controller:

```powershell
Invoke-Command -ComputerName COMP01 -ScriptBlock {
    Get-Printer |
        Format-Table Name, DriverName, PortName, PrinterStatus -AutoSize
}
```

**Observed error:**

```text
The spooler service is not reachable.
Ensure the spooler service is running.

FullyQualifiedErrorId : HRESULT 0x800706ba,Get-Printer
```

**Interpretation:**

Windows could not communicate with the printing subsystem. The error suggested checking the Print Spooler service before investigating individual printer drivers or ports.

### Step 2 — Inspect Print Spooler Service

```powershell
Invoke-Command -ComputerName COMP01 -ScriptBlock {
    Get-Service Spooler |
        Select-Object Name, Status, StartType
}
```

**Observed result:**

```text
Name       : Spooler
Status     : Stopped
StartType  : Disabled
```

**Finding:**

The Print Spooler was not running, and Windows was configured not to start it.

This explained why the system print dialog could not access printing functionality.

### Step 3 — Reproduce the Failure

On COMP01:

1. Opened a document or printable page.
2. Opened the Windows system print dialog.
3. Attempted to print using the available Windows printing interface.
4. Observed the printer unavailable / incorrectly installed error.

**Result:** Printing failure reproduced.

## 5. Root Cause

The Windows Print Spooler service (`Spooler`) had been stopped and its startup type changed to `Disabled`.

The Print Spooler is responsible for managing print jobs and communication with configured printers, including virtual printers such as Microsoft Print to PDF.

**Root cause category:** Local Windows service misconfiguration.

**Lab context:** The fault was deliberately injected for troubleshooting practice. In production, the technician would investigate whether a policy, administrator, security control, or previous change caused the service to be disabled.

## 6. Resolution

The Print Spooler startup configuration was changed to Automatic, and the service was started.

Commands executed remotely from the DC:

```powershell
Invoke-Command -ComputerName COMP01 -ScriptBlock {
    Set-Service Spooler -StartupType Automatic
    Start-Service Spooler

    Get-Service Spooler |
        Select-Object Name, Status, StartType

    Get-Printer |
        Select-Object Name, PrinterStatus
}
```

### Explanation of Commands

| Command | Purpose |
|---|---|
| `Invoke-Command` | Executes PowerShell remotely |
| `-ComputerName COMP01` | Specifies the target workstation |
| `-ScriptBlock {}` | Contains commands executed on the target |
| `Set-Service` | Modifies service configuration |
| `-StartupType Automatic` | Configures automatic service startup |
| `Start-Service` | Starts the service immediately |
| `Get-Service` | Retrieves service information |
| `Get-Printer` | Enumerates configured printers |
| `Select-Object` | Returns selected object properties |
| `\|` | Pipes command output into another command |

**Key distinction:**

`Set-Service -StartupType Automatic` changes startup configuration but does not itself start the service.

`Start-Service Spooler` starts the service in the current session.

Both commands were necessary for this remediation.

## 9. Lessons Learned

### Troubleshooting

- Reproduce the user's issue before modifying the system.
- Investigate the underlying Windows service when printer enumeration fails.
- Distinguish application-level PDF export from printing through Windows.
- Verify both service status and startup configuration.
- Confirm remediation through command-line and GUI testing.
- Do not assume that an accessible Settings page means the underlying service is healthy.

### PowerShell

- `Get-*` commands commonly retrieve information.
- `Set-*` commands modify configuration.
- `Start-*`, `Stop-*`, and `Restart-*` control service state.
- PowerShell Remoting allows authorized administration of endpoints without accessing their desktop.
- Previously documented commands can be reused as operational runbooks.

### Operational Considerations

In a production environment, a disabled Print Spooler might be intentional, especially on systems where printing is not required.

Before changing a service's startup configuration, confirm that the service is expected to be enabled and that the change complies with organizational policy.
