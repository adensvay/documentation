
# INC-032 — Active Directory User Account Disabled

**Date:** October 23, 2026  
**Priority:** P3 — Medium  
**Status:** Remediated — AD State Verified  
**Category:** Identity & Access Management / Active Directory  
**Environment:** Windows Server 2022 / Active Directory Domain Services  
**Domain:** `aden.local`  
**Affected User:** John Smith (`jsmith`)

---

## 1. Incident Summary

### User Report

> "Hi IT, I tried signing in to my work account this morning, but Windows won't let me in. I was able to sign in yesterday using the same password."

### Business Impact

The user was unable to authenticate to their domain account, preventing access to their Windows workstation and domain resources.

### Objective

- Investigate the user's Active Directory account.
- Identify the authentication restriction.
- Determine whether the account was disabled or locked out.
- Restore account access after appropriate authorization.
- Verify the account's state.

**Lab context:** This incident was simulated using a real Active Directory user object in my Windows Server 2022 homelab.

## 3. Initial Investigation

### Step 1 — Contact the User

I requested additional information before making changes to the account.

**Technician:**

> "Hey John, sorry to hear that. Are you seeing any error messages as you attempt to sign in?"

**Simulated user response:**

> "When I enter my username and password, Windows says: 'Your account has been disabled. Please see your system administrator.'"

**Interpretation:**

The error suggested an account-level restriction rather than an incorrect password or workstation connectivity issue.

Possible causes included:

- Account disabled by an administrator.
- Account locked due to failed authentication attempts.
- Account expiration.
- Organizational security or HR restrictions.

The exact error message made a disabled account the primary hypothesis.

---

## 4. Active Directory Investigation

### Step 2 — Inspect the User in ADUC

Opened:

    Server Manager
      > Tools
      > Active Directory Users and Computers

Located:

    aden.local
      > Users / User OU
      > John Smith (jsmith)

**Observation:**

The account displayed a downward-arrow overlay on its user icon.

This icon indicates that an Active Directory account is disabled.

### Disabled vs. Locked-Out Accounts

| Condition | Meaning |
|---|---|
| Disabled | Administrator has explicitly prevented the account from authenticating |
| Locked Out | Account has been locked, typically following repeated failed authentication attempts |
| Expired | Account has passed its configured expiration date |
| Password Expired | Password must be changed before normal authentication can continue |

**Important distinction:**

A disabled account and a locked-out account are not the same condition.

Unlocking an account does not automatically enable it.

---

## 5. Remediation

### Step 3 — Correct the Account State

Using Active Directory Users and Computers, I investigated the user's account restrictions and attempted to restore account access.

My initial troubleshooting focused on the account lockout setting.

However, the account's disabled state required separate attention.

For a disabled account, the relevant ADUC action is:

    Right-click user
      > Enable Account

This should only be performed after confirming the account was not intentionally disabled by HR, security, or another administrator.

**Lab note:** The final AD state was confirmed through PowerShell. The exact sequence of ADUC actions that restored the account was not independently captured.

---

## 6. PowerShell Verification

### Step 4 — Inspect Account Status

Command executed on the domain controller:

    Get-ADUser -Identity jsmith -Properties Enabled,LockedOut |
        Select-Object Name,Enabled,LockedOut

Result:

    Name         Enabled   LockedOut
    ----         -------   ---------
    John Smith   True      False

**Interpretation:**

- `Enabled = True`: The account is enabled.
- `LockedOut = False`: The account is not currently locked out.

**Result: PASS**

The account no longer had either of these two restrictions.

This verified the AD account state but did not independently prove a successful interactive sign-in.

---

## 7. Final Verification and Outcome

### Verified

- The `jsmith` account exists in Active Directory.
- The account is enabled.
- The account is not locked out.
- The account state was inspected directly on the domain controller.

### Not Independently Verified

- Successful interactive sign-in from a domain-joined Windows workstation.
- End-to-end authentication against the domain controller.

The simulated user confirmed successful access as part of the ticket exercise.

**Final Status:** Remediated — AD account state verified.

# 8. Reusable Active Directory PowerShell Commands

The following commands can be reused for future account authentication tickets.

Run them from a domain controller or an authorized administrative workstation with the Active Directory PowerShell module installed.

## A. Load Active Directory Module

    Import-Module ActiveDirectory

## B. Retrieve Basic User Information

    Get-ADUser -Identity jsmith

Retrieve commonly useful account properties:

    Get-ADUser -Identity jsmith -Properties * |
        Select-Object Name,
                      SamAccountName,
                      Enabled,
                      LockedOut,
                      AccountExpirationDate,
                      PasswordExpired,
                      PasswordLastSet,
                      LastLogonDate

**Note:** `LastLogonDate` is a replicated, approximate logon timestamp and should not be treated as an exact real-time logon record.

## C. Check Whether an Account Is Enabled

    Get-ADUser -Identity jsmith |
        Select-Object Name,Enabled

Expected output for an enabled account:

    Name         Enabled
    ----         -------
    John Smith   True

## D. Check Whether an Account Is Locked

    Get-ADUser -Identity jsmith -Properties LockedOut |
        Select-Object Name,LockedOut

Expected output for an unlocked account:

    Name         LockedOut
    ----         ---------
    John Smith   False

## E. Check Both Conditions Together

    Get-ADUser -Identity jsmith -Properties Enabled,LockedOut |
        Select-Object Name,Enabled,LockedOut

This is a useful first command when investigating account access issues.

## F. Enable a Disabled Account

**Administrative privileges and authorization required.**

    Enable-ADAccount -Identity jsmith

Verify:

    Get-ADUser -Identity jsmith |
        Select-Object Name,Enabled

**Caution:** Do not enable an account without determining why it was disabled.

An account may have been intentionally disabled during offboarding, a security incident, or an HR action.

## G. Disable an Account

**Administrative privileges and authorization required.**

    Disable-ADAccount -Identity jsmith

Verify:

    Get-ADUser -Identity jsmith |
        Select-Object Name,Enabled

Common use cases:

- Employee offboarding.
- Security containment.
- Temporary access suspension.

Disabling an account is different from deleting it.

## H. Unlock a Locked-Out Account

    Unlock-ADAccount -Identity jsmith

Verify:

    Get-ADUser -Identity jsmith -Properties LockedOut |
        Select-Object Name,LockedOut

**Important:** Unlocking an account does not enable a disabled account.

## I. Find Locked-Out Accounts

    Search-ADAccount -LockedOut -UsersOnly

Useful for investigating account lockout incidents across the domain.

## J. Find Disabled Accounts

    Search-ADAccount -AccountDisabled -UsersOnly

Useful for audits and account lifecycle reviews.

## K. Check Account Expiration

    Get-ADUser -Identity jsmith -Properties AccountExpirationDate |
        Select-Object Name,AccountExpirationDate

Check for expired accounts:

    Search-ADAccount -AccountExpired -UsersOnly

## L. Check Password Expiration

    Get-ADUser -Identity jsmith -Properties PasswordExpired,PasswordLastSet |
        Select-Object Name,PasswordExpired,PasswordLastSet

Force a password change at next logon when appropriate:

    Set-ADUser -Identity jsmith -ChangePasswordAtLogon $true

**Note:** Forcing a password change is not a fix for a disabled account.

## M. Check Group Membership

    Get-ADPrincipalGroupMembership -Identity jsmith |
        Select-Object Name

Useful when a user can sign in but cannot access a specific application, shared folder, or resource.

## N. Check Domain Controller Connectivity

    nltest /dsgetdc:aden.local

This helps locate a domain controller for the specified domain.

Check basic AD service discovery:

    nltest /dclist:aden.local

These commands are useful when investigating broader domain authentication or connectivity problems.

## 10. Key Lessons Learned

### 1. Disabled and Locked-Out Are Different

A disabled account is administratively prevented from authenticating.

A locked-out account is restricted by account lockout controls.

The remediation commands are different:

    Enable-ADAccount

versus:

    Unlock-ADAccount

### 2. The Exact Error Message Matters

The user's reported error was:

    Your account has been disabled.

This provided a direct clue toward the root cause.

Asking the user for the exact error message should be an early troubleshooting step.

### 3. ADUC Icons Provide Useful Visual Clues

A downward-arrow overlay on an AD user icon generally indicates a disabled account.

However, visual inspection should be supplemented with PowerShell verification.

### 4. Verify Before Closing

After changing account settings, confirm the resulting state.

For this incident:

    Enabled = True
    LockedOut = False

In production, also verify the user can successfully authenticate.

### 5. Never Automatically Re-enable Accounts

An account may be disabled intentionally.

Before restoring access:

- Verify the user's identity.
- Confirm employment or account ownership.
- Review the ticket or change history.
- Check for HR or security restrictions.
- Obtain authorization when required.

### 6. Administrative Tools Can Fail

During lab preparation, attempts to modify the `logonHours` attribute using `Set-ADUser` failed.

Lessons:

- `Set-ADUser` does not expose every AD attribute as a dedicated parameter.
- Some attribute changes may not be supported through a particular cmdlet or interface.
- A script printing a success message does not prove that the preceding command succeeded.
- Verify the actual AD object state after any scripted modification.

For PowerShell automation, use terminating errors where appropriate:

    $ErrorActionPreference = "Stop"

And verify changes explicitly before reporting success.
