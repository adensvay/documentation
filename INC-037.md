## 1. Incident Summary

A simulated employee reported that Windows Search was no longer returning expected file results.

The employee could browse files manually through File Explorer but could not reliably locate documents using Windows Search.

Investigation revealed that the Windows Search service (`WSearch`) was stopped and its startup type was set to `Disabled`.

The service was reconfigured and restarted successfully. Windows subsequently reported that indexing was complete, with 459 items indexed.

## 4. Initial Investigation

### Windows Search Warning

I opened the Windows Search interface and observed the following message:

```text
Search indexing was turned off.
Turn indexing back on.
```

This indicated that Windows Search indexing was not functioning normally.

### What Is Windows Search Indexing?

Windows Search indexing is a background process that maintains a searchable database of files, filenames, metadata, and supported document contents.

The index allows Windows to retrieve search results without repeatedly scanning every file.

The Windows Search service (`WSearch`) supports this functionality.

If the service is disabled or stopped, indexing can become unavailable and search results may be incomplete.

---

## 5. Service Investigation

### Command Executed

```powershell
Get-Service -Name WSearch |
    Format-List Name, DisplayName, Status, StartType
```

### Output

```text
Name        : WSearch
DisplayName : Windows Search
Status      : Stopped
StartType   : Disabled
```

### Findings

Two important properties were identified:

**Status: Stopped**

The Windows Search service was not currently running.

**StartType: Disabled**

Windows was configured to prevent the service from starting.

This explained why Windows reported that search indexing was turned off.

### Root Cause Identified

The Windows Search service had been disabled.

Because the service was stopped and disabled, Windows Search indexing could not operate normally.

---

## 6. Remediation

The remediation required two changes:

1. Reconfigure the Windows Search service to allow automatic startup.
2. Start the service.

### Step 1 — Change Startup Type

Command executed:

```powershell
Set-Service -Name WSearch -StartupType Automatic
```

This changed the startup configuration from `Disabled` to `Automatic`.

The command did not immediately start the service.

### Step 2 — Start Windows Search

Command executed:

```powershell
Start-Service -Name WSearch
```

This started the Windows Search service.

### Step 3 — Verify Service Configuration

Command executed:

```powershell
Get-Service -Name WSearch |
    Format-List Name, DisplayName, Status, StartType
```

### Output

```text
Name        : WSearch
DisplayName : Windows Search
Status      : Running
StartType   : Automatic
```

### Result

The service was successfully restored.

The startup configuration was changed from disabled to automatic, and the service was running.

**Note:** This configuration uses `Automatic` startup rather than `Automatic (Delayed Start)`. The latter can be configured separately if required.

## 11. Lessons Learned

### Windows Service Administration

Windows services have two separate operational properties:

- **Startup type:** Determines how or whether a service can start.
- **Status:** Indicates whether the service is currently running.

A service configured as `Disabled` generally cannot be started until its startup configuration is changed.

### PowerShell Administration

I learned how to use:

```powershell
Get-Service
```

to inspect service status.

```powershell
Set-Service
```

to modify service startup configuration.

```powershell
Start-Service
```

to start a stopped Windows service.

These commands are useful for troubleshooting many Windows components and third-party applications.

### Verification

A successful PowerShell command does not automatically prove that the original user problem has been resolved.

Verification should occur at multiple levels:

1. Confirm the service configuration.
2. Confirm the underlying Windows component is operational.
3. Confirm the user can perform the originally affected task.

### Troubleshooting Process

This incident followed the sequence:

```text
User reports missing search results
        |
        v
Observe Windows Search warning
        |
        v
Inspect WSearch service
        |
        v
Identify Stopped / Disabled state
        |
        v
Change startup type
        |
        v
Start service
        |
        v
Verify Running / Automatic
        |
        v
Inspect Indexing Options
        |
        v
Confirm indexing complete
```
