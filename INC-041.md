## 1. Incident Summary

A simulated employee reported being unable to access his domain account despite previously having working credentials.

An investigation in Active Directory Users and Computers (ADUC) revealed that the user's account had expired on October 26, 2026.

After obtaining simulated manager authorization, the account expiration was extended through December 31, 2026.

PowerShell verification confirmed that the account was enabled, unlocked, no longer expired, and did not require a password change.

A fresh workstation sign-in remained outstanding at the time of documentation.

## 4. Initial Investigation

The technician opened Active Directory Users and Computers on DC01 and located the `jsmith` account.

Navigation:

1. Open Active Directory Users and Computers.
2. Locate John Smith.
3. Right-click the account and select Properties.
4. Open the Account tab.
5. Inspect account restrictions and expiration settings.

### Finding

Under **Account expires**, the account was configured with:

```text
End of: Monday, October 26, 2026
```

The incident occurred on October 28, 2026.

The account had therefore expired two days earlier.

### Preliminary Diagnosis

The account expiration setting was a likely cause of the user's authentication failure.

An expired AD account can prevent domain authentication even when the user enters the correct password.

---

## 5. Authorization and Access Governance

Before modifying the expiration date, the technician requested clarification regarding the user's continued access authorization.

### Simulated Manager Response

> John Smith is an active employee. His account expiration was not intended, and his access should remain active. Please extend his account expiration to December 31, 2026.

### Approved Action

Extend John Smith's AD account expiration through December 31, 2026.

### IAM Consideration

In a production environment, helpdesk technicians should not arbitrarily extend user account expiration dates.

Changes should follow the organization's access management policy and require authorization from an appropriate manager, HR representative, or IAM administrator.

This helps prevent unauthorized account reactivation or unnecessary extension of access.

## 6. Remediation

The technician updated the account expiration using Active Directory Users and Computers.

### Steps Performed

1. Opened John Smith's account properties.
2. Selected the Account tab.
3. Located the Account expires section.
4. Selected End of.
5. Changed the expiration date to December 31, 2026.
6. Saved the updated account properties.

### Updated ADUC Setting

```text
Account expires:
End of: Thursday, December 31, 2026
```

No password reset, account unlock, or group membership change was performed.

## 8. Understanding the Expiration Timestamp

ADUC displayed:

```text
Thursday, December 31, 2026
```

PowerShell displayed:

```text
1/1/2027 12:00:00 AM
```

These values represent the same effective account expiration boundary.

When an account is configured to expire at the end of December 31, Active Directory may expose the timestamp as midnight at the beginning of January 1.

This is not evidence that the account received an extra day of access.

---

## 9. Additional Finding — Logon Workstation Restrictions

The account inspection revealed:

```text
LogonWorkstations : WIN-8QGPUAN7QO8,COMP01
```

This indicates that the account has an explicit list of permitted logon workstations.

### Significance

Even with a valid password and an unexpired account, workstation restrictions can prevent a user from logging on to an unauthorized computer.

The technician did not modify these restrictions because they were not established as the cause of the current incident.

### Lesson

Avoid changing unrelated account security settings while resolving a specific authentication issue.

Use the principle of least privilege and preserve existing restrictions unless there is an approved reason to change them.

## 10. Root Cause Analysis

**Root Cause:** Expired Active Directory user account.

The account was configured to expire on October 26, 2026, before the October 28 incident.

The user was therefore outside the account's authorized validity period.

### Root Cause Classification

Identity lifecycle management / Account expiration configuration.

### Lab Cause

A deliberately injected AD account expiration fault.

### Production Considerations

In a real organization, potential underlying causes could include:

- Incorrect onboarding or provisioning expiration date.
- Temporary access not extended following contract renewal.
- Administrative configuration error.
- Failure to update an account after an employment status change.

The actual cause of the expiration setting would need to be confirmed through the organization's records or audit logs.

## 13. Lessons Learned

### 1. Valid Credentials Do Not Guarantee Account Access

A user may know the correct password but still be unable to authenticate because of account restrictions.

Account expiration, account disablement, lockouts, password expiration, and workstation restrictions should be considered during authentication troubleshooting.

### 2. Account Expiration Is an IAM Lifecycle Control

Account expiration helps organizations enforce time-limited access for temporary workers, contractors, and other users with defined access periods.

Extending expiration dates requires appropriate authorization.

### 3. ADUC and PowerShell Complement Each Other

ADUC provides a graphical interface for inspecting and changing account properties.

PowerShell enables repeatable inspection, filtering, verification, and documentation.

Both tools were useful during this incident.

### 4. Verify Changes After Applying Them

The technician did not rely solely on the ADUC expiration field.

A subsequent PowerShell query confirmed the updated account state.

### 5. Preserve Unrelated Security Restrictions

The account had workstation logon restrictions.

Because these were not established as the root cause, they were left unchanged.

### 6. Administrative Verification Is Not the Same as User Verification

Healthy account properties indicate that an identified restriction has been corrected.

A successful interactive sign-in provides stronger evidence that the user can actually access the intended workstation.
