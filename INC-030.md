
# INC-030 — Windows 11 Network Connectivity Failure (APIPA / DHCP)

**Status:** Resolved  
**Priority:** P3 — Medium  
**Environment:** Windows 11 Enterprise (COMP02)  
**Category:** Network / DHCP / IPv4 Configuration  
**Resolution:** Restored DHCP configuration and renewed IPv4 lease

---

## 1. Incident Summary

A Sales department user reported losing internet connectivity and access to company network resources after restarting their workstation.

Other employees were unaffected, suggesting a workstation-specific issue rather than a network-wide outage.

**Affected Device:** COMP02  
**Network Adapter:** Ethernet0

### Reported Symptoms
- Unable to access the internet.
- Unable to reach company network resources.
- Issue began after workstation restart.
- Other workstations reportedly remained operational.

## 2. Initial Investigation

Opened PowerShell on COMP02 and tested external IP connectivity.

```powershell
ping 8.8.8.8
```

**Result:**
- Four requests failed.
- Error: `PING: transmit failed. General failure.`
- No successful responses.

Next, tested DNS resolution.

```powershell
nslookup google.com
```

**Result:**
- DNS query failed.
- No response from the configured DNS server.

Inspected the workstation's network configuration.

```powershell
ipconfig /all
```

**Findings:**

| Property | Value |
|---|---|
| Hostname | COMP02 |
| Adapter | Ethernet0 |
| DHCP Enabled | No |
| IPv4 Address | 169.254.241.129 |
| Subnet Mask | 255.255.0.0 |
| Default Gateway | None |
| DNS Servers | IPv6 entries |

The workstation had a link-local IPv4 address in the `169.254.0.0/16` range, commonly associated with Automatic Private IP Addressing (APIPA).

No usable IPv4 default gateway was configured.

Most importantly, DHCP was disabled on the network adapter.

## 3. Root Cause Analysis

**Root Cause:** DHCP was disabled on COMP02's Ethernet0 interface.

Without DHCP enabled, the workstation could not automatically request a valid IPv4 lease from the network's DHCP server.

The workstation had a link-local APIPA address instead of an address belonging to the local network.

Because no valid IPv4 default gateway was configured, the workstation could not route IPv4 traffic to external networks.

### Technical Concepts

- **DHCP:** Automatically provides IP addresses and other network configuration information to clients.
- **APIPA:** Allows Windows to self-assign a `169.254.x.x` address when no usable IPv4 configuration is available.
- **Default Gateway:** Routes traffic to destinations outside the local subnet.
- **DNS:** Resolves domain names to IP addresses.

An APIPA address alone does not prove that the DHCP server is unavailable. In this incident, the adapter configuration showed that DHCP was disabled locally.

## 4. Resolution

Re-enabled DHCP on the affected network interface.

```powershell
Set-NetIPInterface `
    -InterfaceAlias "Ethernet0" `
    -AddressFamily IPv4 `
    -Dhcp Enabled
```

Attempted to remove a previously referenced APIPA address.

```powershell
Remove-NetIPAddress `
    -InterfaceAlias "Ethernet0" `
    -IPAddress "169.254.77.25" `
    -Confirm:$false
```

**Result:** No matching IP address was found. This command was unnecessary for the successful resolution.

Reset the adapter's DNS server configuration to automatic assignment.

```powershell
Set-DnsClientServerAddress `
    -InterfaceAlias "Ethernet0" `
    -ResetServerAddresses
```

Requested a new DHCP lease.

```powershell
ipconfig /renew
```

**Result:** COMP02 successfully obtained an IPv4 address.

## 5. Post-Resolution Verification

Ran:

```powershell
ipconfig /all
```

**Updated Configuration:**

| Property | Value |
|---|---|
| DHCP Enabled | Yes |
| IPv4 Address | 192.168.254.78 |
| Subnet Mask | 255.255.255.0 |
| Default Gateway | 192.168.254.254 |
| DHCP Server | 192.168.254.254 |
| DNS Server | 192.168.254.254 |
| Connection Suffix | home |

The workstation successfully acquired a DHCP lease from the local network.

Performed additional connectivity tests:

```powershell
ping 192.168.254.254
ping 8.8.8.8
nslookup google.com
```

**Results:**
- Gateway connectivity: Successful.
- External IPv4 connectivity: Successful.
- DNS resolution: Successful.

**Final Status:** Internet connectivity and DNS functionality restored. Access to internal company resources was not separately verified.

## 6. Lessons Learned

1. A `169.254.x.x` address is an important indicator of missing usable IPv4 configuration, but does not independently establish the root cause.
2. `ipconfig /all` provides essential information about DHCP status, assigned addresses, DNS servers, and default gateways.
3. Testing an external IP address separately from a hostname helps distinguish connectivity issues from DNS resolution problems.
4. A missing default gateway can prevent access to resources outside the local subnet.
5. DHCP configuration should be verified before assuming the DHCP server itself has failed.
6. Successful remediation should be followed by connectivity and DNS verification.
