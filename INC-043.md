**Affected User:** John Smith (`jsmith`)  
**Environment:** Windows Server 2022 / Active Directory / Microsoft Entra ID  
**Status:** Resolved

## 1. Incident Summary

A simulated employee reported that his department information in Microsoft 365 did not reflect a recent HR update.

The employee's on-premises Active Directory account was functioning normally, but his cloud profile displayed incorrect or outdated organizational information.

Investigation revealed that the employee's `department` attribute in Active Directory had been changed to `Legacy Operations`, despite HR confirming that his correct department was `IT`.

During troubleshooting, the technician also discovered that the environment was running **Microsoft Entra Connect Sync**, rather than Microsoft Entra Cloud Sync as initially assumed.

After identifying the installed synchronization engine, the technician used PowerShell to initiate a delta synchronization and confirmed that the on-premises department attribute was being propagated to Microsoft Entra ID.

The incorrect department was corrected in Active Directory, synchronized, and verified.

**Outcome:** The employee's department was restored to `IT`, and the hybrid identity synchronization workflow was validated.

## 8. Investigation — Identifying the Synchronization Engine

The technician initially searched for an active Microsoft Entra Cloud Sync configuration.

However, no Cloud Sync configuration was visible in the Entra admin center.

This prompted an investigation of the synchronization services installed on DC01.

### Initial Service Discovery

```powershell
Get-Service |
    Where-Object {
        $_.DisplayName -match "Entra|Azure AD Connect|Provisioning|Synchronization"
    } |
    Select-Object Name,DisplayName,Status
```

### Output

```text
Name                       DisplayName                              Status
----                       -----------                              ------
AzureADConnectAgentUpdater Microsoft Azure AD Connect Agent Updater Running
AzureADConnectHealthAgent  Microsoft Entra Connect Health Agent    Running
vmictimesync               Hyper-V Time Synchronization Service    Stopped
```

The initial service search identified Entra-related components but did not establish which synchronization engine was active.

### Expanded Service Discovery

```powershell
Get-Service |
    Where-Object {
        $_.Name -match "AADConnect|AzureADConnect|ADSync" -or
        $_.DisplayName -match "Provisioning Agent|Microsoft Azure AD Connect"
    } |
    Select-Object Name,DisplayName,Status,StartType
```

### Output

```text
Name                       DisplayName                               Status StartType
----                       -----------                               ------ ---------
ADSync                     Microsoft Azure AD Sync                  Running Automatic
AzureADConnectAgentUpdater Microsoft Azure AD Connect Agent Updater Running Automatic
AzureADConnectHealthAgent  Microsoft Entra Connect Health Agent     Running Automatic
```

### Finding

The `ADSync` service was installed and running.

This indicated that the environment was using the Microsoft Entra Connect Sync engine.

## 9. Verifying the ADSync PowerShell Module

The technician checked whether the ADSync PowerShell module was available.

### Command

```powershell
Get-Module -ListAvailable ADSync
```

### Output

```text
Directory: C:\Program Files\Microsoft Azure AD Sync\Bin

ModuleType Version Name   ExportedCommands
---------- ------- ----   ----------------
Binary     1.0.0.0 ADSync {Add-ADSyncApplicationRegistration, ...}
```

### Finding

The ADSync module was installed locally on DC01.

This confirmed that PowerShell synchronization commands could be executed through the installed Entra Connect Sync engine.

### Technical Distinction

Microsoft Entra Connect Sync and Microsoft Entra Cloud Sync are different synchronization technologies.

**Entra Connect Sync:**

- Uses a locally installed synchronization engine.
- Runs the ADSync Windows service.
- Supports manually initiated delta synchronization.
- Exposes the `Start-ADSyncSyncCycle` PowerShell command.

**Entra Cloud Sync:**

- Uses cloud-managed provisioning with an on-premises agent.
- Has a separate configuration and management workflow.
- Does not use the ADSync delta synchronization command.

The technician's initial difficulty came from looking for a Cloud Sync configuration when the environment was actually running Entra Connect Sync.

## 10. Delta Synchronization

After identifying the correct synchronization engine, the technician imported the ADSync PowerShell module.

### Command

```powershell
Import-Module ADSync
```

The technician then initiated a delta synchronization.

```powershell
Start-ADSyncSyncCycle -PolicyType Delta
```

### Actual Output

```text
Result
------
Success
```

### Interpretation

The synchronization engine accepted the delta synchronization request.

A successful result indicates that the synchronization cycle was initiated successfully.

It does not, by itself, guarantee that every individual attribute was exported successfully.

Destination-side verification is still necessary.

## 11. Verification — Incorrect Attribute Propagated

After the delta synchronization, the technician refreshed John's Microsoft Entra profile.

The previously blank department field now displayed:

```text
Job Information

Department: Legacy Operations
```

### Finding

The incorrect department value had successfully propagated from Active Directory to Entra ID.

This demonstrated that:

- The synchronization engine was operational.
- The department attribute was included in synchronization.
- The on-premises department value was being transferred to Entra.
- The initial blank field was not sufficient evidence of a broken synchronization configuration.

### Important Distinction

At this stage, synchronization was working, but the synchronized data was incorrect.

**A functioning synchronization system can still propagate incorrect source data.**

The issue therefore required correction in the authoritative directory rather than changes to the synchronization engine.

## 14. Root Cause Analysis

### Primary Root Cause

An incorrect `department` attribute was present in the employee's on-premises Active Directory account.

```text
Incorrect: Legacy Operations
Correct:   IT
```

Because Active Directory was authoritative for the synchronized user attribute, the incorrect value propagated into Microsoft Entra ID.

### Secondary Troubleshooting Finding

The synchronization technology was initially misidentified.

The technician searched for a Microsoft Entra Cloud Sync configuration, but the environment was running Microsoft Entra Connect Sync.

This caused unnecessary uncertainty about how to initiate synchronization.

### Root Cause Classification

**Primary:** Identity data integrity / Incorrect AD attribute

**Secondary:** Synchronization engine identification / Administrative tooling

### Resolution

1. Identified the correct synchronization engine.
2. Verified the ADSync service was running.
3. Confirmed the ADSync PowerShell module was installed.
4. Initiated a delta synchronization.
5. Verified that the incorrect department propagated to Entra.
6. Corrected the authoritative AD attribute.
7. Synchronized the corrected value.
8. Verified the final configuration.

## 16. Lessons Learned

### 1. Identify the Authoritative Identity Source

In hybrid Microsoft environments, synchronized attributes may be controlled by on-premises Active Directory.

Attempting to modify these attributes directly in Entra may be inappropriate or blocked.

Always determine which directory owns the attribute before making changes.

### 2. Verify the Installed Synchronization Technology

Microsoft Entra Connect Sync and Microsoft Entra Cloud Sync have different management workflows.

A technician should not assume which synchronization engine is installed.

Checking Windows services and PowerShell modules provides useful evidence.

### 3. A Successful Delta Sync Does Not Guarantee Correct Data

The delta synchronization successfully propagated `Legacy Operations` into Entra.

The synchronization engine was functioning, but the source information was incorrect.

This demonstrates the distinction between:

- Synchronization health
- Identity data accuracy

Both must be verified independently.

### 4. Correct the Source Before Synchronizing

In production, the preferred workflow is:

```text
Verify HR-approved information
           |
           v
Inspect on-premises AD
           |
           v
Correct authoritative attribute
           |
           v
Synchronize
           |
           v
Verify Microsoft Entra ID
```

Synchronizing before correcting the source can propagate incorrect data.

### 5. Use Read-Only Diagnostics Before Making Changes

Commands such as `Get-ADUser`, `Get-Service`, and `Get-Module` help identify the issue without modifying the environment.

This reduces the risk of unnecessary configuration changes.

### 6. Understand Synchronization Timing

Changes in Active Directory do not always appear immediately in Microsoft Entra ID.

Technicians should account for scheduled synchronization cycles, processing delays, and provisioning errors.

### 7. Verify Both Ends of a Hybrid Identity Workflow

A successful PowerShell command does not necessarily mean the employee's cloud profile is correct.

Verification should include the source directory and the destination directory.
