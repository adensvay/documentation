## Root Cause

The user's Active Directory account was configured with a workstation
logon restriction permitting authentication only from `COMP99`.

The user's currently assigned workstation was `COMP01`.

As a result, Active Directory rejected the user's authentication attempt
from COMP01 and Windows reported that the account was configured to
prevent use of the computer.

## Investigation

The user reported being unable to authenticate specifically to their
workstation.

I requested the exact Windows error message and verified the user's
identity and department.

The error indicated that the account was not permitted to use the
computer.

I inspected the user's Active Directory account properties and found
a workstation restriction under:

Account > Log On To

The account permitted:

`COMP99`

while the user's assigned workstation was:

`COMP01`

This established the root cause as an incorrect AD workstation
restriction rather than a password, account lockout, or Entra issue.

## Resolution

Confirmed that COMP01 was the user's assigned workstation.

Updated the user's Active Directory workstation restriction from
COMP99 to COMP01.

I initially considered allowing the user to log onto all computers,
but determined that doing so would unnecessarily broaden the user's
authorized access.

No Group Policy update was required because the issue involved an
Active Directory user attribute rather than a GPO.

## Verification

- Confirmed the user's AD logon workstation configuration
- Corrected authorized workstation to COMP01
- User successfully authenticated to COMP01
- User confirmed normal workstation access

## Lessons Learned

- Exact user-facing error messages can significantly narrow the
  troubleshooting scope.
- AD workstation restrictions can limit which domain computers an
  individual account may authenticate to.
- Restoring access is not sufficient by itself; the intended access
  state should be established before changing permissions.
- Expanding access to "All computers" would have resolved the symptom
  but granted broader access than necessary.
- `gpupdate /force` is relevant to Group Policy processing, not every
  Active Directory account change.
- Authentication issues should be differentiated between account state,
  credentials, workstation restrictions, policy, and cloud identity.
