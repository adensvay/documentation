## 4. Provisioning Olivia Bennett

### Dry-Run Creation — Executed

```powershell
New-ADUser `
    -Name "Olivia Bennett" `
    -GivenName "Olivia" `
    -Surname "Bennett" `
    -SamAccountName "obennett2" `
    -UserPrincipalName "obennett2@adensvaygmail.onmicrosoft.com" `
    -Path "OU=Users,OU=USA,DC=aden,DC=local" `
    -Department "Sales" `
    -Title "Sales Representative" `
    -EmployeeID "EMP-1045" `
    -Manager "rbrooks" `
    -Enabled $false `
    -WhatIf
```

### Observed Output

```text
What if: Performing the operation "New" on target
"CN=Olivia Bennett,OU=Users,OU=USA,DC=aden,DC=local".
```

The dry run did not create the user.

An attempted group assignment and account lookup immediately afterward returned `ADIdentityNotFoundException`, because the account had not yet been created.

This reinforced the difference between previewing a change and executing it.

### Actual Creation

The same `New-ADUser` operation was subsequently executed without `-WhatIf`.

### Verification — Executed

```powershell
Get-ADUser obennett2 -Properties `
    UserPrincipalName,Department,Title,Manager,EmployeeID,Enabled |
    Format-List Name,SamAccountName,UserPrincipalName,
        Department,Title,Manager,EmployeeID,Enabled
```

### Verified Results

## 7. Hybrid Synchronization to Microsoft Entra ID

Microsoft Entra Connect Sync transfers eligible on-premises directory changes into Microsoft Entra ID.

### Delta Synchronization Command

```powershell
Start-ADSyncSyncCycle -PolicyType Delta
```

If the command is unavailable:

```powershell
Import-Module ADSync
Start-ADSyncSyncCycle -PolicyType Delta
```

A successful synchronization request commonly returns:

```text
Result
------
Success
```

**Important:** This result means the synchronization request was accepted. It does not independently verify that both users were synchronized successfully.

## 9. PowerShell Lessons Learned

### `-WhatIf` — Safe Change Preview

The `-WhatIf` parameter previews supported administrative operations without applying them.

Example:

```powershell
New-ADUser ... -WhatIf
```

Observed benefit:

- Confirmed the intended target OU before provisioning.
- Reduced the risk of accidental changes.
- Provided a safe way to review operations before execution.

Important limitation:

**`-WhatIf` is not a full validation or testing environment.**

It does not create a temporary object, guarantee the subsequent command will succeed, or verify downstream permissions and dependencies.

### Idempotency and Duplicate Checks

A provisioning script should check whether an identity already exists before attempting to create it.

Repeated execution should not accidentally create duplicate accounts or overwrite unrelated users.

### Explicit Verification

A PowerShell command completing without an error does not necessarily prove that the full onboarding request is complete.

Verify actual state with commands such as:

```powershell
Get-ADUser
Get-ADPrincipalGroupMembership
```

Then separately validate synchronization and cloud access.

### Identity Source of Authority

For synchronized accounts, on-premises AD is generally the source of authority for synchronized identity attributes.

Make applicable changes in AD and allow them to synchronize rather than attempting to edit read-only synchronized attributes in Entra.
