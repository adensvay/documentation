
# INC-040 — Network Printer IP Misconfiguration

**Date:** October 27, 2026  
**Category:** Windows Desktop Support / Network Printing  
**Priority:** P3 — Medium  
**Affected Workstation:** COMP02  
**Operating System:** Windows 11  
**Environment:** VMware Workstation / Physical Network Printer  
**Status:** Resolved — Verified and Cleaned Up

---

## 1. Incident Summary

A simulated employee reported that a network printer was installed on their Windows workstation but was unable to print documents.

The physical printer was operational, and network connectivity from COMP02 had previously been verified.

Investigation revealed that the affected Windows printer queue was assigned to a Standard TCP/IP port configured with an incorrect destination IP address.

The incorrect destination was unreachable, while the actual printer was accessible on TCP port 9100.

The printer queue was reassigned to the correct TCP/IP port, and successful printing was verified using a physical test page.

Temporary printer queues and ports were subsequently removed.

## 8. Fault Injection — Incorrect Printer Destination

The objective was to simulate a workstation whose printer queue referenced an incorrect IP address.

### Initial Attempt — Unsupported Command

```powershell
Set-PrinterPort `
    -Name "INC040-TCPIP" `
    -PrinterHostAddress "192.0.2.123"
```

### Error

```text
Set-PrinterPort : The term 'Set-PrinterPort' is not recognized
as the name of a cmdlet, function, script file, or
operable program.
```

### Finding

`Set-PrinterPort` was not an available PowerShell cmdlet.

The attempted command made no changes to the printer configuration.

### Corrected Approach

Instead of modifying the existing port, a second Standard TCP/IP port was created with the incorrect destination.

```powershell
Add-PrinterPort `
    -Name "INC040-WrongIP" `
    -PrinterHostAddress "192.0.2.123" `
    -PortNumber 9100
```

The temporary printer queue was then assigned to this port.

```powershell

    -Name "INC040-HP-Test" `
    -PortName "INC040-WrongIP"
```

### Verify the Assigned Port

## 9. Troubleshooting the Network Failure

The printer's configured destination was compared against the known-good printer IP.

### Test 1 — Incorrect Destination

```powershell
Test-NetConnection -ComputerName 192.0.2.123 -Port 9100
```

### Output

```text
WARNING: TCP connect to (192.0.2.123 : 9100) failed
WARNING: Ping to 192.0.2.123 failed with status: TimedOut

ComputerName           : 192.0.2.123
RemoteAddress          : 192.0.2.123
RemotePort             : 9100
InterfaceAlias         : Ethernet0
SourceAddress          : 192.168.254.78
PingSucceeded          : False
PingReplyDetails (RTT) : 0 ms
TcpTestSucceeded       : False
```

### Interpretation

COMP02 could not reach the incorrect destination over TCP port 9100.

The ping test also timed out.

The address `192.0.2.123` belongs to a documentation-reserved address range and was used solely for this lab.

### Test 2 — Actual Printer Destination

```powershell
Test-NetConnection -ComputerName 192.168.254.168 -Port 9100
```

### Output

```text
ComputerName     : 192.168.254.168
RemoteAddress    : 192.168.254.168
RemotePort       : 9100
InterfaceAlias   : Ethernet0
SourceAddress    : 192.168.254.78
TcpTestSucceeded : True
```

### Comparison

| Destination | TCP Port | Result |
|---|---|---|
| 192.0.2.123 | 9100 | Failed |
| 192.168.254.168 | 9100 | Successful |

### Diagnostic Conclusion

The printer itself was reachable through the correct IP address.

The temporary Windows printer queue was configured to send jobs to an incorrect destination.

The evidence supported a local printer port misconfiguration rather than a physical printer failure.

## 10. Root Cause

**Root Cause:** Incorrect Standard TCP/IP printer port assignment.

The affected printer queue was assigned to:

```text
PortName: INC040-WrongIP
PrinterHostAddress: 192.0.2.123
PortNumber: 9100
```

The actual printer was reachable at:

```text
PrinterHostAddress: 192.168.254.168
PortNumber: 9100
```

The misconfiguration caused the queue to target an unreachable network destination.

### Root Cause Classification

Endpoint printer configuration / Incorrect network destination.

**Lab cause:** Deliberate fault injection.

## 16. Lessons Learned

### 1. A Printer Queue Is Not a Physical Printer

Windows can maintain multiple printer queues pointing to the same physical device.

Each queue may use different ports, drivers, permissions, or default settings.

Creating a second queue does not create another physical printer or introduce an IP conflict.

### 2. WSD and Standard TCP/IP Ports Are Different

The original HP printer used a WSD port.

The temporary test queue used a Standard TCP/IP port with a defined destination address and TCP port number.

Understanding the connection type is important when diagnosing printer connectivity.

### 3. Printer Status Is Not Definitive

Windows reported `PrinterStatus : Normal` while the temporary queue was configured with an unreachable destination.

A healthy-looking queue does not prove that print jobs can reach the printer.

### 4. Compare the Configured Destination Against a Known-Good Address

The incorrect address failed:

```text
192.0.2.123:9100 → TcpTestSucceeded: False
```

The actual printer succeeded:

```text
192.168.254.168:9100 → TcpTestSucceeded: True
```

This comparison helped isolate the problem to the printer queue's destination configuration.

### 5. Use Supported PowerShell Cmdlets

`Set-PrinterPort` was not available.

The supported approach was to create a new port using `Add-PrinterPort` and assign it using `Set-Printer`.

### 6. Printer Queues and Ports Are Separate Resources

Deleting a printer queue does not automatically remove its associated port.

Both resources may require separate cleanup.

### 7. The Print Spooler May Retain Port References

The temporary TCP/IP port initially could not be removed because Windows reported it was still in use.

After confirming that no printer queue referenced the port, restarting the Print Spooler allowed the port to be removed.

### 8. Verify Recovery with a Physical Print Test

A successful `Test-NetConnection` proves TCP connectivity, not necessarily end-to-end printing.

A physical test page provided stronger verification that the repaired printer queue was operational.
