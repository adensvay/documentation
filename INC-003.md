## INC-1007 — User Unable to Sign Into Domain Workstation

### Environment
- Windows Server 2022 Domain Controller
- Active Directory Domain Services
- Windows 11 domain-joined client
- Domain: `aden.local`
- User: `jsmith`
- Workstation: `COMP01`

### User Report
The user reported being unable to sign into their normal Windows workstation despite believing their password was correct.

The Windows login screen displayed an error indicating that the account was configured to prevent the user from using the PC.

### Initial Investigation
Because the error specifically referenced authorization to use the workstation, I investigated the user's Active Directory account rather than immediately resetting the password.

In Active Directory Users and Computers:

`User Properties → Account → Log On To`

I discovered that `jsmith` had a workstation restriction configured, but the permitted workstation was not the user's actual computer.

Configured workstation:

`SALESS-PC99`

Actual workstation:

`COMP01`

### Root Cause
The user's `userWorkstations` Active Directory attribute contained an incorrect workstation.

Because the account was configured to log on only to specified computers, Windows rejected the domain login from `COMP01`.

### Resolution
I removed the incorrect workstation and added:

`COMP01`

I intentionally preserved the workstation restriction instead of changing the account to **All computers**, following least-privilege principles and restoring the intended configuration rather than unnecessarily broadening access.

Equivalent PowerShell:

Set-ADUser -Identity jsmith -LogonWorkstations "COMP01"

Verification:

Get-ADUser jsmith -Properties LogonWorkstations |
Select-Object SamAccountName, LogonWorkstations

### Validation
The user attempted another login to `COMP01` and confirmed that authentication succeeded.

Ticket status:

`New → Active → Waiting on Client → Resolved`

### Key Takeaways
- A correct password does not necessarily mean a user is authorized to log into a particular workstation.
- AD's **Log On To** setting restricts which domain computers an account can use for interactive login.
- Domain-joined computers have computer objects in Active Directory.
- `COMP01` can therefore be referenced as an allowed workstation for a domain user.
- Avoid removing security restrictions simply because doing so resolves the immediate symptom.
- Prefer restoring the intended configuration and validating the result with the user.
