
# INC-042 — Microsoft Entra ID Security Group Membership Restoration

**Affected User:** Daniel Kim  
**Affected Group:** SG-Sales  
**Environment:** Microsoft Entra ID  
**Status:** Resolved — Group Membership Restored

---

## 1. Incident Summary

A simulated Sales department employee reported losing access to departmental resources despite previously having appropriate permissions.

The investigation focused on Microsoft Entra ID security group membership.

An initial review showed that the `SG-Sales` security group contained four direct members, compared to five members recorded in the pre-incident inventory.

By comparing the original and current membership lists, the technician identified Daniel Kim as the missing member.

Daniel was subsequently restored to `SG-Sales`.

A final inspection of the Entra admin center confirmed that the group once again contained all five original members.

This incident demonstrated identity-based authorization troubleshooting, group membership auditing, and access restoration using Microsoft Entra ID.

## 5. Fault Injection

A PowerShell script was used to simulate an unexpected group membership change.

The script:

1. Connected to Microsoft Graph.
2. Located the existing `SG-Sales` security group.
3. Selected an existing direct group member.
4. Removed the selected membership.
5. Saved the original membership information for restoration.

The technician was not informed which user had been removed.

### Injection Mechanism

The relevant Microsoft Graph operation was:

```powershell
Remove-MgGroupMemberByRef `
    -GroupId $group.Id `
    -DirectoryObjectId $selected.Id
```

The command removes a directory object's direct membership from a specified Entra group.

**Safety Note:** Group membership changes can affect application access, resource authorization, and potentially licensing or policy assignments. These operations should only be performed in authorized environments.

## 8. Root Cause Analysis

**Root Cause:** Missing direct membership in the Microsoft Entra ID `SG-Sales` security group.

### Expected Configuration

```text
User: Daniel Kim
Group: SG-Sales
Membership: Present
```

### Faulty Configuration

```text
User: Daniel Kim
Group: SG-Sales
Membership: Missing
```

### Root Cause Classification

Identity and Access Management / Group-based authorization.

### Lab Cause

A deliberate group membership removal introduced through Microsoft Graph PowerShell.

### Potential Production Causes

In a real environment, an unexpected group membership change could result from:

- An administrator removing the wrong user.
- An incorrect onboarding or offboarding operation.
- Automated identity lifecycle processing.
- A group membership synchronization issue.
- An unauthorized administrative change.

The specific cause of a production change should be established through audit logs rather than assumed.

## 9. Remediation

After identifying the missing membership, Daniel Kim was restored to the existing `SG-Sales` security group through the Microsoft Entra admin center.

### Administrative Steps

1. Open Microsoft Entra Admin Center.
2. Navigate to Entra ID.
3. Select Groups.
4. Open All groups.
5. Select SG-Sales.
6. Open Members.
7. Select Add members.
8. Locate Daniel Kim.
9. Add Daniel to the group.
10. Refresh the membership list.

### Result

Daniel Kim was restored as a direct member of `SG-Sales`.

No other group memberships were intentionally changed during remediation.

## 11. Microsoft Graph PowerShell Command Reference

These commands are useful for future Entra ID IAM incidents.

### Connect to Microsoft Graph

```powershell
Connect-MgGraph -Scopes "Group.Read.All","User.Read.All"
```

Use read-only scopes for initial investigation.

### Check the Current Graph Connection

```powershell
Get-MgContext
```

This displays information about the authenticated Graph session, including the tenant and granted scopes.

### Find a Security Group

```powershell
Get-MgGroup -Filter "displayName eq 'SG-Sales'" |
    Select-Object Id,DisplayName,SecurityEnabled
```

### List Direct Group Members

```powershell
$group = Get-MgGroup -Filter "displayName eq 'SG-Sales'"

Get-MgGroupMemberAsUser -GroupId $group.Id -All |
    Select-Object DisplayName,UserPrincipalName,Id
```

### Count Group Members

```powershell
$group = Get-MgGroup -Filter "displayName eq 'SG-Sales'"

@(
    Get-MgGroupMemberAsUser -GroupId $group.Id -All
).Count
```

### Find a User by Display Name

```powershell
Get-MgUser -Filter "displayName eq 'Daniel Kim'" |
    Select-Object Id,DisplayName,UserPrincipalName
```

If multiple users have the same display name, identify the correct account using its UPN or object ID.

### Check a User's Direct Group Memberships

```powershell
$user = Get-MgUser -Filter "displayName eq 'Daniel Kim'"

Get-MgUserMemberOf -UserId $user.Id -All
```

This returns directory objects. Additional property inspection or group-specific queries may be needed to display readable group names.

### Connect with Group Modification Permissions

```powershell
Connect-MgGraph -Scopes `
    "Group.Read.All", `
    "GroupMember.ReadWrite.All", `
    "User.Read.All"
```

Membership modifications require appropriate Graph permissions and administrative authorization.

### Restore a Missing Group Membership

```powershell
$group = Get-MgGroup -Filter "displayName eq 'SG-Sales'"
$user = Get-MgUser -Filter "displayName eq 'Daniel Kim'"

New-MgGroupMemberByRef `
    -GroupId $group.Id `
    -BodyParameter @{
        "@odata.id" = "https://graph.microsoft.com/v1.0/directoryObjects/$($user.Id)"
    }
```

**Important:** Verify that the group and user queries return exactly one intended object before performing the modification. This example is a reference command, not a transcript of the GUI-based remediation.

### Remove a Group Member

```powershell
Remove-MgGroupMemberByRef `
    -GroupId $group.Id `
    -DirectoryObjectId $user.Id
```

Only perform this operation when removal has been authorized.

### Verify Membership After Remediation

```powershell
$group = Get-MgGroup -Filter "displayName eq 'SG-Sales'"

Get-MgGroupMemberAsUser -GroupId $group.Id -All |
    Select-Object DisplayName,UserPrincipalName |
    Sort-Object DisplayName
```

## 12. Recommended Production Follow-Up — Audit Logs

In a production environment, restoring membership should not necessarily conclude the investigation.

The technician should determine why the membership changed.

### Entra Admin Center Navigation

```text
Microsoft Entra Admin Center
  > Entra ID
  > Monitoring & health
  > Audit logs
```

### Suggested Investigation

Review group membership change events involving:

```text
Group: SG-Sales
User: Daniel Kim
Activity: Remove member from group
```

Look for:

- Timestamp of the removal.
- Initiating administrator or application.
- Target group.
- Affected user.
- Whether the change was authorized.
- Any related automation or identity governance activity.

### Security Consideration

An unexplained membership removal may indicate an administrative mistake, an automation problem, or an unauthorized change.

The technician should document the findings and escalate suspicious activity when appropriate.

## 13. Lessons Learned

### 1. Group Membership Is a Core Authorization Mechanism

Microsoft Entra security groups can be used to manage access to applications and other resources.

An incorrect membership can result in users gaining or losing access.

### 2. Establish a Known-Good Baseline

The original group inventory was essential to identifying Daniel Kim as the missing member.

Without a baseline or approved access record, the technician would need additional authorization evidence before restoring membership.

### 3. Do Not Assume the Reported User Is the Affected Identity

The initial simulated requester, Marcus Lee, was still a member of the Sales security group.

The technician's inspection revealed that the actual missing member was Daniel Kim.

Troubleshooting should follow technical evidence rather than assumptions.

### 4. Direct and Transitive Membership Are Different

A user may receive access through direct or nested group membership, depending on the resource and supported group types.

This incident specifically involved direct membership in `SG-Sales`.

### 5. Restore Only the Required Access

The remediation restored Daniel's original membership without intentionally changing other users or groups.

This aligns with least-privilege IAM administration.

### 6. Group Membership Does Not Prove Resource Access

Restoring an Entra security group membership confirms that the directory configuration has been corrected.

End-to-end verification may additionally require testing the actual application or resource.

### 7. Investigate Unexpected Identity Changes

Restoring access resolves the immediate directory issue, but production IAM teams should also review audit logs to determine why the change occurred.
